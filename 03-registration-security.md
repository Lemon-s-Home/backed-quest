# 03. Регистрация и безопасность

Рассмотрим кратко, как принимать данные регистрации, хранить пароли и безопасно показывать пользователей. Добавим пароль, проверим повторную регистрацию и отправим запросы напрямую через `curl.exe`. Затем временно уберём защиту вывода и увидим, как сохранённое имя превращается в выполняемый браузером код.

Пример выполним на PHP, а выводы о проверке данных и защите вывода относятся к бэкенду на любом языке. Запросы отправляем в своё приложение по `127.0.0.1`. Все пароли в примерах учебные.

## 1. Подготовь копию приложения

Останови сервер. Рядом с `lesson-02` создай папку `lesson-03`. Скопируй в неё `users.json` и папку `public` из второго урока. Дальше работай в копии.

```text
lesson-03/
    users.json
    public/
        index.php
```

В PowerShell перейди в `lesson-03`. JSON по-прежнему находится вне `public`. Пример второго урока останется без изменений.

## 2. Раздели три действия

Когда сервер получает поля формы, ему нужны разные операции:

| Операция | Пример в нашем приложении |
|---|---|
| Нормализация | Убрать пробелы по краям почты и привести её к нижнему регистру |
| Валидация | Проверить длину имени, формат почты и наличие пароля |
| Экранирование при выводе | Показать `<script>` в имени как текст, а не как HTML-тег |

Нормализация приводит данные к выбранному виду. Валидация решает, можно ли их принять. Экранирование выполняется там, где данные вставляются в HTML.

Правило нашего учебного сайта: почту сравниваем без учёта регистра. Поэтому `Anna@example.com` и `anna@example.com` считаем одним адресом. Это решение приложения, а не обещание, что все почтовые системы обрабатывают регистр одинаково.

Пароль не обрезаем через `trim()`: пробел может быть частью выбранного пароля.

## 3. Добавь пароль

Сначала проверь, что твоя сборка PHP поддерживает выбранный алгоритм:

```powershell
php -r "echo implode(', ', password_algos());"
```

В списке должен быть `argon2id`: этот пример требует PHP с его поддержкой.

Замени содержимое `public/index.php`:

```php
<?php

$usersFile = dirname(__DIR__) . '/users.json';
$path = parse_url($_SERVER['REQUEST_URI'], PHP_URL_PATH);
$method = $_SERVER['REQUEST_METHOD'];
$error = '';
$status = 400;

if (!in_array($path, ['/users', '/register'], true)) {
    http_response_code(404);
    exit('Страница не найдена');
}

if ($method === 'POST' && $path === '/register') {
    $contentType = strtolower(trim(explode(';', $_SERVER['CONTENT_TYPE'] ?? '')[0]));
    $length = (int) ($_SERVER['CONTENT_LENGTH'] ?? 0);
    if ($contentType !== 'application/x-www-form-urlencoded') {
        http_response_code(415);
        exit('Ожидаются данные HTML-формы');
    }
    if ($length < 1 || $length > 8192) {
        http_response_code(413);
        exit('Размер формы должен быть от 1 до 8192 байт');
    }
    foreach (['name', 'email', 'password'] as $field) {
        if (!isset($_POST[$field]) || !is_string($_POST[$field])) {
            $error = 'Ожидаются имя, почта и пароль в виде строк';
            break;
        }
    }
    if ($error === '') {
        $name = trim($_POST['name']);
        $email = strtolower(trim($_POST['email']));
        $password = $_POST['password'];
        if (preg_match('/\A.{1,80}\z/us', $name) !== 1) {
            $error = 'Имя: от 1 до 80 символов';
        } elseif (strlen($email) > 254 || preg_match('/\A[a-z0-9._+-]+@[a-z0-9-]+(?:\.[a-z0-9-]+)+\z/', $email) !== 1) {
            $error = 'Проверь адрес почты';
        } elseif (preg_match('/\A.{12,128}\z/us', $password) !== 1 || str_contains($password, "\0")) {
            $error = 'Пароль: от 12 до 128 символов, без нулевого символа';
        }
    }
    $users = json_decode(file_get_contents($usersFile), true, 512, JSON_THROW_ON_ERROR);
    if ($error === '') {
        foreach ($users as $user) {
            if (strtolower(trim($user['email'])) === $email) {
                $error = 'Эта почта уже зарегистрирована';
                $status = 409;
                break;
            }
        }
    }
    if ($error === '') {
        $ids = array_column($users, 'id');
        $nextId = $ids === [] ? 1 : max($ids) + 1;
        $users[] = [
            'id' => $nextId,
            'name' => $name,
            'email' => $email,
            'password_hash' => password_hash($password, PASSWORD_ARGON2ID, [
                'memory_cost' => 19456,
                'time_cost' => 2,
                'threads' => 1,
            ]),
        ];
        $json = json_encode($users, JSON_UNESCAPED_UNICODE | JSON_PRETTY_PRINT | JSON_THROW_ON_ERROR);
        if (file_put_contents($usersFile, $json . "\n") === false) {
            throw new RuntimeException('Не удалось сохранить пользователей');
        }
        header('Location: /users', true, 303);
        exit;
    }
    http_response_code($status);
} elseif ($method !== 'GET') {
    http_response_code(405);
    header('Allow: ' . ($path === '/register' ? 'GET, POST' : 'GET'));
    exit('Метод не поддерживается для этой страницы');
}

$users = $path === '/users'
    ? json_decode(file_get_contents($usersFile), true, 512, JSON_THROW_ON_ERROR)
    : [];
header('Content-Type: text/html; charset=utf-8');
?>
<!doctype html>
<html lang="ru">
<head><meta charset="utf-8"><title>Регистрация</title></head>
<body>
    <nav><a href="/users">Пользователи</a> | <a href="/register">Регистрация</a></nav>
    <?php if ($path === '/users'): ?>
        <h1>Пользователи</h1>
        <ul>
            <?php foreach ($users as $user): ?>
                <li><?= htmlspecialchars($user['name'], ENT_QUOTES, 'UTF-8') ?> — <?= htmlspecialchars($user['email'], ENT_QUOTES, 'UTF-8') ?></li>
            <?php endforeach; ?>
        </ul>
    <?php else: ?>
        <h1>Регистрация</h1>
        <?php if ($error !== ''): ?>
            <p><?= htmlspecialchars($error, ENT_QUOTES, 'UTF-8') ?></p>
        <?php endif; ?>
        <form action="/register" method="post">
            <p><label>Имя: <input name="name" required></label></p>
            <p><label>Почта: <input name="email" type="email" required></label></p>
            <p><label>Пароль: <input name="password" type="password" minlength="12" maxlength="128" required></label></p>
            <button type="submit">Зарегистрироваться</button>
        </form>
    <?php endif; ?>
</body>
</html>
```

Запусти из `lesson-03`:

```powershell
php -S 127.0.0.1:8000 -t public public/index.php
```

Открой `/register`, добавь пользователя с почтой `browser@example.com` и проверь хеш в JSON. `password_hash` сама создаёт соль и строку Argon2id. Функцию обратного получения пароля мы не пишем: её нет.

Проверка `is_string` нужна потому, что отправитель может прислать вместо строки массив. Вызов `trim` на таком значении без проверки привёл бы к ошибке выполнения. Регулярные выражения проверяют длину имени и пароля в символах UTF-8 без дополнительного расширения PHP.


### Разбери проверки

Сначала проверяем, что пришла обычная форма и её размер не превышает 8192 байта. Затем разбираем поля, проверяем данные и ищем уже зарегистрированную почту. Только после этого вычисляем хеш и меняем файл. На отклонённом запросе JSON остаётся прежним.

Регулярное выражение задаёт ограниченный формат почты нашего сайта: латинские буквы, цифры и перечисленные знаки, один `@`, домен с точкой. Это не полное описание всех допустимых адресов и не проверка существования ящика.

`409 Conflict` означает конфликт с уже имеющимися данными — у нас с занятой почтой. `413` сообщает о недопустимом размере тела, `415` — о неподдерживаемом формате. Для невалидных полей возвращаем знакомый `400`.

Граница размера полезна, но не решает все вопросы: например, клиент может медленно передавать разрешённое тело. Наш учебный сервер остаётся локальным примером, а не готовым публичным сервисом.

## 4. Отправь запрос без браузерной формы

Сервер уже работает. Теперь открой второе окно PowerShell. `curl.exe` отправляет HTTP-запросы из консоли; суффикс `.exe` выбирает именно эту программу, а не одноимённую команду старого PowerShell.

Сначала добавь пользователя корректным запросом:

```powershell
curl.exe -i --data-urlencode "name=Console User" --data-urlencode "email=console@example.com" --data-urlencode "password=study-only-passphrase-2026" http://127.0.0.1:8000/register
```

`--data-urlencode` кодирует значения полей и помещает их в тело запроса. При таких параметрах curl сам выбирает `POST` и формат обычной формы. `-i` показывает статус и заголовки ответа.

Получишь `303` и `Location: /users`. curl без дополнительного указания не переходит по перенаправлению, поэтому открой `/users` в браузере сам. Проверь запись в списке и JSON.

Сервер принял данные, хотя страницу с формой мы вообще не открывали. Теперь понятно, почему `required` и `minlength` в браузере не являются защитой сервера.

### Пропусти пароль

```powershell
curl.exe -i --data-urlencode "name=No Password" --data-urlencode "email=no-password@example.com" http://127.0.0.1:8000/register
```

Ожидается `400`. Нового пользователя в файле нет.

### Передай короткий пароль

```powershell
curl.exe -i --data-urlencode "name=Short Password" --data-urlencode "email=short@example.com" --data-urlencode "password=123" http://127.0.0.1:8000/register
```

Ожидается `400`. curl не проверяет атрибут `minlength` нашей формы: отказал именно сервер.

### Передай неверную почту

```powershell
curl.exe -i --data-urlencode "name=Wrong Email" --data-urlencode "email=not-an-email" --data-urlencode "password=study-only-passphrase-2026" http://127.0.0.1:8000/register
```

Ожидается `400`, файл не меняется.

### Попробуй занять существующую почту

```powershell
curl.exe -i --data-urlencode "name=Another User" --data-urlencode "email=CONSOLE@example.com" --data-urlencode "password=another-study-password-2026" http://127.0.0.1:8000/register
```

Ожидается `409`. Новая запись не появляется, старый хеш не меняется. Иначе повторная «регистрация» могла бы перезаписать чужие данные или создать неоднозначность при входе.

## 5. Сохрани код в имени и открой список

Отправь ещё один запрос:

```powershell
curl.exe -i --data-urlencode "name=<script>alert(1)</script>" --data-urlencode "email=xss@example.com" --data-urlencode "password=study-only-passphrase-2026" http://127.0.0.1:8000/register
```

Наше правило имени проверяет длину, поэтому ответ будет `303`. В JSON сохранится имя с тегами. Открой `/users`: вместо окна с числом 1 должен появиться буквальный текст `<script>alert(1)</script>` в пункте списка.

Почему код не выполнился? При выводе имени вызывается `htmlspecialchars($user['name'], ENT_QUOTES, 'UTF-8')`. В HTML-ответе угловые скобки заменены на `&lt;` и `&gt;`. Браузер показывает их как символы текста, не как границы тега.

### Временно убери защиту вывода

В `public/index.php` временно замени только вставку имени внутри `<li>`:

```php
<?= $user['name'] ?>
```

Здесь намеренно убрана `htmlspecialchars` у имени. Сохрани и открой `/users`. PHP выполняет файл заново при каждом запросе; перезапуск не нужен. Браузер выполнит сохранённый `<script>` и покажет окно с числом 1. Закрой его.

Новый POST не понадобился: вредоносная строка уже лежала в JSON. Она выполняется при просмотре списка — в том числе у другого посетителя. Это хранимая XSS: сохранённые данные превращаются в код браузера.

В нашем опыте код только открывает окно. В настоящем приложении чужой JavaScript выполнялся бы в контексте сайта и мог бы читать доступное странице содержимое и отправлять действия от имени посетителя. Это не выполнение PHP-кода и не прямой запуск команд на сервере.

### Верни защиту и повтори

Верни безопасную вставку:

```php
<?= htmlspecialchars($user['name'], ENT_QUOTES, 'UTF-8') ?>
```

Сохрани и обнови `/users`. Окно больше не появляется, имя видно текстом. Запись в JSON при этом осталась той же. Открой исходный код ответа (`Ctrl+U`) и найди `&lt;script&gt;`.

Удалять теги при сохранении — не замена экранированию при выводе. Можно ввести более строгое правило для имён, но данные приходят также из импортов, старых записей и других форм. Кроме того, кавычки и другие символы важны по-разному внутри текста и HTML-атрибутов. Здесь мы защищаем конкретное место вывода, а исходные данные храним отдельно. [Почему защита зависит от места вывода](https://cheatsheetseries.owasp.org/cheatsheets/Cross_Site_Scripting_Prevention_Cheat_Sheet.html).

Убедись, что `htmlspecialchars` возвращена.


## 6. Проверь, что данные не утекают целиком

В консоли выполни:

```powershell
curl.exe -i http://127.0.0.1:8000/users.json
```

Ожидается `404`, без содержимого файла. Файл находится вне `public`, а наш обработчик возвращает `404` для этого пути.

Открой исходный код `/users` и поищи `$argon2id$`: хешей там быть не должно. На странице выводятся только конкретные разрешённые поля. Нельзя просто отправить посетителю весь объект пользователя после добавления пароля в структуру.

Хеширование уменьшает последствия утечки, но не делает утечку допустимой: имена, почта и хеши тоже не должны быть доступны произвольному посетителю как файл. Публичный список имён и почты — выбранное поведение нашего учебного сайта; в настоящем продукте доступ к нему определяют отдельно.

Останови работающий учебный сервер. Сохрани `public/index.php` с восстановленным экранированием. Тестовую запись с `<script>` можно удалить из JSON после завершения опыта.

## 7. Сравни защиты

| Попытка | Что защищает | Как проверили |
|---|---|---|
| Отправить поля без открытия формы | Серверная валидация | curl обошёл браузер, но получил `400` |
| Занять чужую почту повторно | Проверка уже сохранённых адресов | Ответ `409`, старая запись не изменилась |
| Выполнить HTML из имени | Экранирование в месте вывода | С тем же JSON опасная и безопасная версии дают разный результат |
| Получить исходный пароль из файла | Парольный хеш с солью | В JSON есть хеш, открытого пароля нет |
| Скачать все данные | Разделение файлов и публичных маршрутов | `/users.json` вернул `404` |

Мы всё ещё используем последовательный учебный сервер и JSON. Два одновременно пишущих процесса могут нарушить проверку уникальности и затереть изменения: проверка в коде не заменяет ограничение уникальности и транзакцию в базе данных. Наш следующий шаг — проверять пароль при входе и хранить состояние входа, а не считать эту регистрацию законченным публичным сервисом.

## Шпаргалка

- Браузерные ограничения помогают заполнить форму; сервер проверяет любой пришедший запрос.
- Нормализация, валидация и экранирование решают разные задачи.
- Пароль не обрезаем и не сохраняем открытым текстом.
- Argon2id вычисляет хеш; случайная соль входит в его сохранённую строку.
- `409` — почта уже занята, `400` — данные не прошли проверку.
- Данные из JSON тоже нельзя вставлять в HTML без экранирования.
- Хранимая XSS запускается при просмотре ранее сохранённых данных.
- Пароль и его хеш не выводятся в список пользователей.

## Напоследок

1. Одинаковый пароль не обязан давать одинаковую строку хеша. Случайная соль мешает узнать по простому сравнению строк, что два пользователя выбрали один пароль. Соль хранится вместе с хешем и не считается секретом. [Как PHP хеширует пароль](https://www.php.net/manual/en/function.password-hash.php).

2. Argon2 победил в Password Hashing Competition в 2015 году. Его вычисление требует не только процессорного времени, но и памяти: это увеличивает цену массового перебора. В уроке используем вариант Argon2id. [Результаты конкурса](https://www.password-hashing.net/).

3. PHP получил `password_hash` в версии 5.5, а поддержку Argon2id — в 7.3. Результат — строка стандартного формата: язык программы не обязан определять формат хранимого хеша. [История функций PHP](https://www.php.net/manual/en/function.password-hash.php).

## Практика

### 3.1. Проверь одинаковые пароли

Зарегистрируй двух пользователей с разной почтой и одинаковым учебным паролем. Проверь в JSON, что хеши различаются и оба начинаются с `$argon2id$`.

Затем попробуй повторно зарегистрировать первого пользователя, изменив только регистр почты. Зафиксируй ответ и проверь, что его прежний хеш остался тем же. Объясни разницу между новым хешем для новой записи и запретом перезаписи существующей.

### 3.2. Защити новую страницу пользователя

Добавь страницу с подробностями одного пользователя: `/profile?id=1`. Получай номер из адреса, находи запись в JSON и выводи только имя и почту. Несуществующий номер должен возвращать `404`, нечисловой — `400`.

Открой профиль тестового пользователя с именем `<script>alert(1)</script>`: оно должно отображаться как текст, без окна. Убедись по исходному коду ответа, что `password_hash` не попал на страницу.
