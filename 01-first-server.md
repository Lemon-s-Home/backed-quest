# 01. Как работает сайт

Рассмотрим кратко, как работает сайт. Создадим страницу на своём компьютере, а затем напишем программу, которая подставляет в неё имя и рассчитывает, сколько осталось накопить. Сначала запустим её с помощью Python, затем повторим на PHP и сравним результат.

Понадобятся редактор, браузер и PowerShell. Python и PHP должны быть установлены в Windows. Все команды ниже вводи в PowerShell.

## 1. Создай страницу

Открой PowerShell. Создай папку для урока и перейди в неё:

```powershell
mkdir first-site
cd first-site
```

Открой эту папку в редакторе. Создай в ней файл `index.html` и вставь:

```html
<!doctype html>
<html lang="ru">
<head>
    <meta charset="utf-8">
    <title>Мой первый сайт</title>
</head>
<body>
    <h1>Моя страница</h1>
    <p>Я учусь создавать сайты.</p>
</body>
</html>
```

Сохрани файл. HTML описывает содержимое страницы. Обозначения в угловых скобках называются тегами:

- `<title>` задаёт название вкладки браузера;
- `<h1>` — главный заголовок на самой странице;
- `<p>` — абзац текста;
- `<meta charset="utf-8">` указывает кодировку, чтобы русский текст отображался правильно.

Открой `index.html` двойным щелчком в Проводнике. Ты увидишь заголовок и абзац. Посмотри на адресную строку: адрес начинается с `file:///`. Браузер открыл файл прямо с диска.

Замени `Моя страница` внутри `<h1>` на `Мой учебный сайт`. Сохрани файл и обнови страницу в браузере. Заголовок изменился, а название вкладки осталось прежним: его задаёт другой тег — `<title>`.

## 2. Запусти сайт с помощью Python

Вернись в PowerShell. В папке `first-site` выполни:

```powershell
python -m http.server 8000 --bind 127.0.0.1
```

Окно PowerShell оставь открытым: сейчас в нём работает программа.

В адресной строке браузера введи:

```text
http://127.0.0.1:8000/
```

Ты увидишь ту же страницу. Но теперь браузер получает её от запущенной программы Python. Программа, которая принимает обращения браузера и отдаёт ему содержимое сайта, называется веб-сервером.

Вместе с Python устанавливается стандартная библиотека — набор готовых модулей для разных задач. Один из них, `http.server`, позволяет запустить простой веб-сервер без установки дополнительных программ. Он удобен для проверки страниц во время разработки. Для постоянной работы публичного сайта его использовать не рекомендуют.

Разберём команду:

- `python` запускает Python;
- `-m http.server` запускает готовый модуль для раздачи файлов из текущей папки;
- `8000` — номер порта, по которому браузер обращается к этой программе;
- `--bind 127.0.0.1` делает сайт доступным только с твоего компьютера.

В адресе `127.0.0.1` означает твой же компьютер, а `:8000` указывает выбранный порт. Начало `http://` говорит браузеру получать страницу у веб-сервера.

Сам `http.server` умеет принимать обращения и с других компьютеров. В нашем запуске доступ ограничен своим компьютером параметром `--bind 127.0.0.1`.

Посмотри в PowerShell: после открытия страницы там появилась запись об обращении браузера. Такое обращение называется запросом. Содержимое, которое программа отправляет обратно, — ответом. В нашем случае ответ содержит HTML из `index.html`.

### Измени страницу

В `index.html` замени абзац:

```html
<p>Эту страницу отдаёт Python.</p>
```

Сохрани файл и обнови страницу в браузере. Ты увидишь новый текст. Перезапускать Python не пришлось: при новом обращении программа прочитала изменённый HTML-файл.

Теперь нажми `Ctrl+C` в PowerShell. Это остановит программу, и снова появится приглашение для ввода команд.

Обнови страницу в браузере. Если сервер остановлен, браузер покажет ошибку соединения: получать страницу по этому адресу больше не у кого. При этом сам `index.html` остался на диске — его по-прежнему можно открыть двойным щелчком.

## 3. Сформируй страницу кодом Python

До сих пор программа отдавала готовый файл. Теперь пусть Python сам вычисляет значения и собирает из них страницу.

Создай в той же папке файл `server.py`. Вставь весь код:

```python
from http.server import BaseHTTPRequestHandler, HTTPServer


class Page(BaseHTTPRequestHandler):
    def do_GET(self):
        name = "Саша"
        goal = 1000
        saved = 350
        remaining = goal - saved

        html = f"""<!doctype html>
<html lang="ru">
<head>
    <meta charset="utf-8">
    <title>Мои накопления</title>
</head>
<body>
    <h1>Привет, {name}!</h1>
    <p>Цель: {goal} рублей.</p>
    <p>Накоплено: {saved} рублей.</p>
    <p>Осталось: {remaining} рублей.</p>
</body>
</html>"""

        body = html.encode("utf-8")
        self.send_response(200)
        self.send_header("Content-Type", "text/html; charset=utf-8")
        self.end_headers()
        self.wfile.write(body)


HTTPServer(("127.0.0.1", 8000), Page).serve_forever()
```

Сохрани файл. Предыдущий сервер должен быть остановлен. В PowerShell выполни:

```powershell
python server.py
```

Открой `http://127.0.0.1:8000/`. На странице должны появиться приветствие «Привет, Саша!» и три суммы: цель — 1000, накоплено — 350, осталось — 650 рублей.

### Разбери код

Начнём с той части, которая определяет содержимое страницы:

```python
name = "Саша"
goal = 1000
saved = 350
remaining = goal - saved
```

В переменных хранятся имя, цель и накопленная сумма. Значение `remaining` вычисляется: из цели вычитается накопленное. Числа 650 в коде нет — его получила программа.

Перед большой строкой HTML стоит буква `f`. В такой строке Python заменяет выражения в фигурных скобках их значениями. Поэтому `{name}` превращается в `Саша`, а `{remaining}` — в `650`. Тройные кавычки позволяют записать строку на нескольких строках.

Остальной код связывает эту страницу с браузером:

- `from ... import ...` подключает готовые части веб-сервера из стандартной библиотеки;
- `Page` описывает, как отвечать браузеру; при открытии страницы выполняется метод `do_GET`;
- `encode("utf-8")` переводит текст в байты для отправки;
- `send_response(200)` сообщает об успешном ответе;
- `send_header(...)` сообщает, что отправляется HTML в кодировке UTF-8;
- `end_headers()` завершает служебную часть ответа, а `wfile.write(body)` отправляет саму страницу;
- последняя строка запускает сервер по знакомому адресу и оставляет его ждать обращений.

### Кто вызывает `do_GET`

`Page` — наш класс, а `BaseHTTPRequestHandler` в скобках — готовый класс, от которого он наследуется. Наследование позволяет использовать уже написанную обработку соединения и добавить собственное поведение: как сформировать страницу.

Имя `Page` мы выбрали сами. Имя `do_GET` задано правилами `BaseHTTPRequestHandler`: для запроса с методом `GET` он ищет и вызывает метод с именем `do_GET`. Регистр букв важен. Это соглашение конкретной библиотеки, а не специальное слово языка Python. В других библиотеках обработчик страницы может называться иначе.

Параметр `self` обозначает текущий объект обработчика. Через него наш метод вызывает готовые методы, например `self.send_response(200)`.

Проверь значение имени на практике:

1. Останови сервер, переименуй `do_GET` в `show_page`, сохрани файл и снова запусти `python server.py`.
2. Обнови страницу. Вместо расчёта увидишь ошибку с кодом `501`: обработка `GET` не реализована. Метод `show_page` существует, но библиотека не знает, что его надо вызвать.
3. Верни имя `do_GET`, сохрани и перезапусти сервер. Обнови страницу: расчёт снова появится.

Когда мы передаём `Page` в `HTTPServer(("127.0.0.1", 8000), Page)`, мы указываем серверу, какой класс использовать для обработки обращений. Дальше библиотека сама создаёт обработчик и вызывает нужный метод. Наш код не вызывает `do_GET` напрямую.

Это называется обработчиком запроса: мы описываем действие, а сервер запускает его при подходящем обращении. [Описание механизма в документации Python](https://docs.python.org/3/library/http.server.html#http.server.BaseHTTPRequestHandler).

### Проследи путь от адреса до страницы

Когда ты открываешь наш адрес, происходит следующее:

1. Браузер обращается к программе по адресу `127.0.0.1` и порту `8000` и запрашивает путь `/`.
2. Сервер вызывает `do_GET`. Внутри метода задаются переменные и вычисляется остаток.
3. Python собирает HTML, заменяя `{name}` и `{remaining}` значениями.
4. Сервер отправляет ответ, а браузер разбирает HTML и отображает заголовок и абзацы.

Браузер в этом обмене называют клиентом: он запрашивает страницу. Клиент и сервер здесь работают на одном компьютере, но это разные программы. У опубликованного сайта сервер обычно работает на другом компьютере, а порядок действий остаётся тем же.

Правила такого обмена называются HTTP. В имени `do_GET` слово `GET` означает запрос на получение содержимого. Ответ состоит из служебной части и тела. Код `200` сообщает об успехе, заголовок `Content-Type` описывает формат, а тело в нашем случае содержит HTML.

Проверь это в браузере. Нажми `F12`, открой вкладку «Сеть» (`Network`) и обнови страницу. Выбери запись с адресом страницы. В заголовках (`Headers`) найди метод `GET`, статус `200` и `Content-Type`. Затем открой ответ (`Response`): там находится HTML с уже подставленным именем и числом 650.

Именно этот HTML получил браузер. Переменных `goal` и `saved` и формулы вычитания в нём нет: они остались в программе на сервере.

Пока оставь служебные строки как есть. Менять будем переменные и HTML внутри `do_GET`.

### Измени данные

В `server.py` замени имя на своё, а `saved = 350` на `saved = 600`. Сохрани файл и обнови страницу.

Ты увидишь прежние значения: работающая программа Python ещё использует загруженный код. В PowerShell нажми `Ctrl+C`, затем запусти снова:

```powershell
python server.py
```

Обнови страницу. Теперь имя должно измениться, а остаток составить 400 рублей. Формулу и HTML ты не менял: программа сама пересчитала остаток и подставила его в страницу.

Раньше мы меняли отдельный HTML-файл, который готовый сервер перечитывал. Теперь меняем саму программу, поэтому в нашем примере нужен перезапуск.

### Добавь вычисление

После строки `remaining = goal - saved` добавь:

```python
weekly = 100
weeks = remaining / weekly
```

А после абзаца «Осталось» внутри HTML добавь:

```html
    <p>Если откладывать по {weekly} рублей в неделю, понадобится {weeks} недели.</p>
```

Сохрани файл, останови Python и снова выполни `python server.py`. Обнови страницу: при остатке 400 рублей получится 4.0 недели. В Python оператор `/` возвращает дробное число даже при делении без остатка.

Мы считаем срок при постоянном взносе, без процентов. Если получится дробное число недель, это доля недели; округление до целого числа взносов добавим позднее.

Останови Python сочетанием `Ctrl+C`, прежде чем переходить к PHP.

## 4. Сформируй такую же страницу на PHP

Создай в той же папке файл `index.php`. Вставь:

```php
<?php

$name = "Саша";
$goal = 1000;
$saved = 350;
$remaining = $goal - $saved;

?>
<!doctype html>
<html lang="ru">
<head>
    <meta charset="utf-8">
    <title>Мои накопления</title>
</head>
<body>
    <h1>Привет, <?= $name ?>!</h1>
    <p>Цель: <?= $goal ?> рублей.</p>
    <p>Накоплено: <?= $saved ?> рублей.</p>
    <p>Осталось: <?= $remaining ?> рублей.</p>
</body>
</html>
```

Сохрани файл. В PowerShell выполни:

```powershell
php -S 127.0.0.1:8000
```

`php` запускает PHP, а параметр `-S` включает его встроенный веб-сервер. Он предназначен для разработки и проверки сайта. Python уже остановлен, поэтому порт свободен.

В браузере открой именно этот адрес:

```text
http://127.0.0.1:8000/index.php
```

Имя файла указали явно, чтобы открыть именно PHP-пример. В папке остался `index.html`, но при наличии обоих файлов по адресу `/` встроенный сервер PHP выбирает `index.php`.

На странице снова появятся имя Саша и остаток 650 рублей. Это начальные значения из нового файла.

### Разбери код

В начале файла между `<?php` и `?>` выполняется PHP-код. Переменные начинаются с `$`, а инструкции заканчиваются точкой с запятой. Вычисление то же, что на Python:

```php
$remaining = $goal - $saved;
```

Дальше идёт HTML. Вставка `<?= $remaining ?>` означает «выведи значение переменной в этом месте». PHP выполняет вычисления и вставки, а браузеру отправляет получившийся HTML.

### Почему на PHP короче

Сравни одну и ту же часть страницы:

Python — фрагмент строки `html`:

```python
html = f"<p>Осталось: {remaining} рублей.</p>"
```

PHP — разметка прямо в `index.php`:

```php
<p>Осталось: <?= $remaining ?> рублей.</p>
```

В Python мы собираем страницу в строке и явно отправляем её через `wfile.write`. В PHP текст за пределами `<?php ... ?>` автоматически попадает в ответ. Поэтому готовую HTML-разметку можно вставить прямо в `.php`-файл: не нужны ни кавычки вокруг всей страницы, ни `echo` для каждого абзаца. Вставка `<?= ... ?>` нужна только там, где выводится результат вычисления.

Такой файл служит шаблоном страницы: общая разметка остаётся постоянной, а отдельные места заполняются значениями. Служебную часть ответа в нашем PHP-примере формирует встроенный сервер.

Python тоже позволяет работать с отдельными HTML-шаблонами при помощи дополнительных библиотек. Здесь мы используем только стандартную библиотеку, чтобы увидеть весь путь формирования ответа.

Проверь границу между кодом и разметкой. Перед закрывающим `</body>` в `index.php` вставь:

```html
<p>Вычисление на сервере: 1000 - 350</p>
```

Сохрани файл и обнови страницу. Браузер покажет `1000 - 350` буквально: в HTML арифметика не выполняется. Теперь замени этот абзац:

```php
<p>Вычисление на сервере: <?= 1000 - 350 ?></p>
```

Снова сохрани и обнови. Теперь увидишь 650: выражение внутри `<?= ... ?>` выполнил PHP.

Открой исходный код страницы через `Ctrl+U`. Найди новый абзац: там уже число 650, без PHP-вставки. Сравни его с `index.php` в редакторе: файл на сервере и полученный браузером HTML — разные вещи.

### Измени данные

В `index.php` замени имя на своё и `$saved = 350;` на `$saved = 600;`. Сохрани файл и обнови страницу `/index.php`.

Ты увидишь новое имя и остаток 400 рублей. Перезапускать PHP не понадобилось: при каждом обращении встроенный сервер заново выполняет этот файл.

### Добавь вычисление

После строки `$remaining = $goal - $saved;` добавь:

```php
$weekly = 100;
$weeks = $remaining / $weekly;
```

После абзаца «Осталось» добавь:

```html
    <p>Если откладывать по <?= $weekly ?> рублей в неделю, понадобится <?= $weeks ?> недели.</p>
```

Сохрани файл и обнови страницу. PHP выведет 4 недели. Это тот же результат расчёта, который Python показал как `4.0`: вывод чисел у языков может различаться.

После проверки останови PHP сочетанием `Ctrl+C`.

## 5. Сравни результат

| Что сделали | Python | PHP |
|---|---|---|
| Сохранили сумму в переменной | `saved = 350` | `$saved = 350;` |
| Вычислили остаток | `remaining = goal - saved` | `$remaining = $goal - $saved;` |
| Записали разметку | Внутри строки `html` | Прямо в `.php`-файле, вне PHP-блоков |
| Отправили страницу | Явно через `wfile.write` | Разметка и вывод PHP автоматически образуют ответ |
| Вставили остаток в HTML | `{remaining}` внутри f-строки | `<?= $remaining ?>` |
| Изменили программу | Сохранили, перезапустили, обновили страницу | Сохранили и обновили страницу |

Различия в перезапуске относятся к этим способам запуска: у других инструментов разработки поведение может быть другим.

В обоих примерах браузер обращается к программе, она вычисляет значения и возвращает HTML. Браузер показывает результат: ему не нужно выполнять наш Python- или PHP-код.

Готовый `index.html` — статическая страница: её содержимое уже записано в файле. Страницу, которую программа формирует при обращении, называют динамической. Она может выглядеть одинаково при каждом открытии, если исходные данные не изменились.

Мы написали первый бэкенд: код на стороне сервера, который готовит содержимое для браузера.

## 6. Открой сайт под нагрузкой

Один посетитель получил страницу быстро. Проверим, что увидит посетитель, если к сайту одновременно обращаются другие.

Скачай [hey для Windows](https://storage.googleapis.com/hey-releases/hey_windows_amd64) — утилиту для отправки множества запросов к сайту. Сохрани её в папку `first-site` под именем `hey.exe`. Для macOS и Linux есть свои версии.

Запусти наш Python-сервер:

```powershell
python server.py
```

Открой страницу `http://127.0.0.1:8000/` в браузере и убедись, что расчёт отображается.

Теперь открой второе окно PowerShell и перейди в папку `first-site`. Первое окно занято сервером, а из второго будем отправлять запросы. Путь к папке можно скопировать из адресной строки Проводника и передать команде `cd` в кавычках.

### Отправь одну пачку

Во втором окне выполни:

```powershell
.\hey.exe -n 100 -c 100 -t 5 http://127.0.0.1:8000/
```

- `.\hey.exe` запускает программу из текущей папки;
- `-n 100` задаёт всего 100 запросов;
- `-c 100` позволяет отправлять до 100 запросов одновременно;
- `-t 5` ограничивает ожидание каждого запроса пятью секундами.

Это 100 попыток получить страницу, а не гарантия 100 успешных ответов. Прочитай отчёт:

| Поле | Что показывает |
|---|---|
| `Total` | Сколько времени занял весь запуск |
| `Slowest` | Время самого медленного завершённого запроса |
| `Requests/sec` | Средняя скорость обработки по отчёту hey |
| `Status code distribution` | Какие HTTP-статусы получены и сколько раз |
| `Error distribution` | Ошибки соединения и ожидания, если они возникли |

Если все ответы успешные, это результат опыта: с этой пачкой сервер справился. Число 100 само по себе не обязано приводить к отказу.

### Повтори пачки в цикле

Сначала приготовь вкладку браузера с нашим сайтом. Во втором PowerShell выполни:

```powershell
while ($true) {
    .\hey.exe -n 100 -c 100 -t 5 http://127.0.0.1:8000/
}
```

`while ($true)` повторяет блок без ограничения числа повторов. Каждая пачка завершается и печатает отчёт, затем начинается следующая. Одновременно работают до 100 запросов, а общее их число растёт.

Пока цикл работает, переключись в браузер и несколько раз обнови страницу сочетанием `Ctrl+F5`. Оно заставляет браузер заново запросить страницу. Посмотри на время загрузки и вкладку «Сеть». Затем вернись во второе окно PowerShell и нажми `Ctrl+C`, чтобы остановить нагрузку. Сервер в первом окне оставь работающим и снова проверь сайт без нагрузки.

Запиши наблюдение: страница открывалась сразу, ждала или не загрузилась? Какие статусы и ошибки были в отчётах hey? Сравни с открытием после остановки цикла.

### Сделай медленную обработку заметной

Если разница почти не видна, смоделируем медленную операцию. В настоящем приложении это может быть ожидание данных от другого сервиса. У нас будет обычная пауза.

Останови Python в первом окне. В начале `server.py`, рядом с импортом из `http.server`, добавь:

```python
import time
```

В метод `do_GET`, перед `name = "Саша"`, добавь строку с тем же отступом, что у `name`:

```python
        time.sleep(0.2)
```

Теперь обработка каждого запроса включает паузу в 0,2 секунды. Сохрани файл и снова запусти `python server.py`. Повтори одну пачку, затем цикл и открытие страницы в браузере.

Наш класс `HTTPServer` обрабатывает запросы по одному. Пока один обработчик ждёт, следующий не выполняется. Для 100 обработок с такой паузой требуется около 20 секунд только на ожидание. Но hey ждёт каждый запрос не дольше пяти секунд: часть запросов может завершиться ошибкой раньше обработки. Браузер тоже конкурирует за обслуживание с hey.

В зависимости от момента обращения ты можешь увидеть:

- обычную страницу с кодом `200`, но после заметной задержки;
- ошибку соединения или ожидания в браузере — HTTP-ответ в этом случае мог вообще не прийти.

Код `500` не появляется автоматически от нагрузки: он означает, что сервер вернул ответ с ошибкой. Таймаут — другая ситуация: клиент не дождался завершения запроса. В hey это может быть ошибка ожидания, а не HTTP-статус.

В окне Python могут появиться сообщения `BrokenPipeError` или об оборванном соединении: клиент уже перестал ждать, а обработчик попытался отправить ответ. Это ещё не означает завершение всего сервера. После остановки нагрузки он может некоторое время разбирать оставшуюся очередь. Проверь, отвечает ли сайт; при необходимости останови и заново запусти сервер.

Важно: это опыт с нашим `server.py` на `HTTPServer`. Команда `python -m http.server` в современных версиях Python использует многопоточный сервер, поэтому её поведение под нагрузкой отличается.

### Повтори на PHP

Останови цикл hey, затем Python. В `index.php` сразу после `<?php` добавь:

```php
usleep(200000);
```

Это пауза в 200 000 микросекунд, то есть те же 0,2 секунды. Запусти `php -S 127.0.0.1:8000` в первом окне. Во втором сначала отправь одну пачку:

```powershell
.\hey.exe -n 100 -c 100 -t 5 http://127.0.0.1:8000/index.php
```

Затем запусти цикл:

```powershell
while ($true) {
    .\hey.exe -n 100 -c 100 -t 5 http://127.0.0.1:8000/index.php
}
```

В браузере открывай именно `/index.php`. Встроенный сервер PHP в Windows тоже выполняет запросы последовательно: медленный запрос задерживает остальные. Сравни наблюдения с Python, затем останови цикл через `Ctrl+C`.

Заверши опыт: останови PHP, удали `usleep(200000);` из PHP, а из Python — `time.sleep(0.2)` и добавленный `import time`. Закрой второе окно PowerShell. Искусственные задержки больше не нужны.

Этот опыт показывает разницу между «сервер запущен» и «посетитель получает страницу вовремя». Чтобы сайт оказался неудобным или недоступным посетителю, процессу не обязательно падать.

## 7. Как это запускают для посетителей

Пока сайт работает только на твоём компьютере. Рабочее окружение, в котором сайт обслуживает настоящих посетителей, называют продакшеном, или коротко продом.

Для него наши учебные серверы не подходят. Документация Python не рекомендует `http.server` для продакшена: в нём только базовые проверки безопасности. Встроенный сервер `php -S` тоже предназначен для разработки и тестирования. Рабочий сайт должен обслуживать много обращений, поддерживать защищённые соединения и продолжать работу после закрытия терминала разработчика.

Один из распространённых вариантов — поставить перед приложением отдельный веб-сервер nginx (читается «энджин-икс»). Он принимает обращения посетителей, может обеспечивать HTTPS — защищённый обмен с браузером — и самостоятельно отдавать готовые файлы: изображения, CSS с оформлением и JavaScript для браузера. Запросы, требующие вычислений, он передаёт программе приложения. Это называют обратным проксированием.

nginx сам не выполняет наш Python- или PHP-код. Рассмотрим на калькуляторе, кто что делает:

1. Браузер посетителя запрашивает страницу у nginx.
2. nginx передаёт обращение программе, которая обслуживает приложение.
3. Эта программа вызывает наш код: он вычитает накопленную сумму из цели и формирует HTML.
4. Получившийся HTML возвращается через nginx в браузер посетителя.

Вычисления выполняет запущенное приложение на Python или PHP. Сейчас важно понимать разделение обязанностей: nginx принимает внешнее обращение, а программа приложения вычисляет остаток и подставляет его в HTML.

В нашем Python-примере приём обращения и вызов `do_GET` обеспечивает `http.server`. На рабочем сайте эти обязанности можно разделить между несколькими программами. Формула `goal - saved` останется прежней, а код подключения к серверу потребуется изменить. Как именно — разберём, когда будем готовить приложение к публикации.

Что даёт nginx по сравнению с учебным запуском:

- может обслуживать много соединений одновременно, не выделяя отдельный обработчик приложения на каждое ожидание передачи данных;
- отдаёт готовые файлы без запуска нашего кода расчёта;
- поддерживает настройку HTTPS и ограничений на обращения;
- может распределять обращения между несколькими запущенными экземплярами приложения.

Но поставить nginx перед единственным медленным обработчиком недостаточно. Если приложение по-прежнему выполняет запросы по одному с паузой, очередь вычислений останется. Для её сокращения нужно ускорять код или организовать одновременную работу нескольких обработчиков. А запуск и восстановление программ после сбоя настраивают отдельно: nginx сам по себе не перезапускает наше приложение.

nginx — распространённый, но не обязательный выбор. Встречаются другие веб-серверы и платформы, которые сами принимают соединения и запускают приложение. Важно различать приём обращений и выполнение прикладного кода, даже если в учебном примере их объединяет одна программа.

Подробнее: [ограничения `http.server`](https://docs.python.org/3/library/http.server.html), [назначение сервера PHP](https://www.php.net/manual/en/features.commandline.webserver.php), [nginx: файлы и проксирование](https://nginx.org/en/docs/beginners_guide.html).

## Шпаргалка

- HTML описывает содержимое страницы; браузер отображает его.
- Веб-сервер принимает запрос браузера и отправляет ответ.
- `127.0.0.1` — твой компьютер, `8000` — выбранный порт.
- `python -m http.server ...` отдаёт готовые файлы; `python server.py` запускает нашу программу формирования страницы.
- `do_GET` — имя обработчика `GET`, которое ожидает `BaseHTTPRequestHandler`. Оно не произвольное.
- Нагрузка может привести к задержкам и таймаутам без падения процесса. Таймаут клиента — не HTTP-статус.
- Учебный сервер позволяет проверить код локально; на проде используют подходящее рабочее окружение.
- nginx принимает обращения и может передавать их приложению; Python или PHP выполняет другая программа.
- В Python подстановка `{name}` работает внутри строки с префиксом `f`.
- В PHP разметка вне PHP-блоков попадает в ответ напрямую, а `<?= $name ?>` вставляет значение.
- HTTP задаёт правила обмена: браузер отправляет запрос, сервер возвращает статус, заголовки и тело ответа.
- В наших примерах вычисления выполняет сервер; браузер получает готовый HTML.
- После изменения `server.py` перезапусти программу; после изменения `index.php` достаточно обновить страницу.
- `Ctrl+C` в PowerShell останавливает сервер.

## Напоследок

1. PHP долго обходился без собственного сервера для разработки: локальный сайт запускали с отдельным веб-сервером, например Apache. Команда `php -S` появилась в PHP 5.4 в 2012 году, чтобы упростить разработку и тестирование. Она позволяет быстро открыть PHP-страницу, но не заменяет рабочее серверное окружение. [Анонс PHP 5.4](https://www.php.net/releases/5_4_0.php), [предложение встроенного сервера](https://wiki.php.net/rfc/builtinwebserver).

2. В Python простой сервер появился гораздо раньше: `SimpleHTTPServer` есть уже в исходниках Python 1.4. В Python 3.0, вышедшем в 2008 году, его объединили с другими серверными модулями под именем `http.server`. Поэтому в старых примерах встречается `SimpleHTTPServer`, а у нас — `http.server`: это история одной библиотеки, а не две обязательные программы для установки. [Исходники Python 1.4](https://github.com/python/cpython/blob/v1.4/Lib/SimpleHTTPServer.py), [переименование модуля](https://docs.python.org/2/library/simplehttpserver.html), [выход Python 3.0](https://docs.python.org/3/whatsnew/3.0.html).

3. В Go стандартная библиотека тоже содержит HTTP-сервер — пакет `net/http`. Но его используют и для рабочих приложений: сервер становится частью самой программы. Он обслуживает соединения независимо друг от друга, поэтому ожидание в одном обработчике не обязательно задерживает все остальные, как в нашем `HTTPServer`. При этом ограничения времени ожидания и другие настройки рабочего сервера всё равно нужно продумать. nginx может стоять перед таким приложением, но отдельный nginx не является обязательным условием запуска любого сайта. [Документация `net/http`](https://pkg.go.dev/net/http). Сам факт наличия сервера в стандартной библиотеке ничего не говорит о его назначении: надо смотреть возможности и ограничения конкретной реализации.

## Практика

Будем делать страницу пользователей. В следующих уроках регистрация будет добавлять новые записи в этот же файл.

Скачай [users.json](./users.json) и положи его в папку `first-site` рядом с `server.py` и `index.php`. Это готовый список из 20 вымышленных пользователей.

JSON — текстовый формат хранения данных. В нашем файле квадратные скобки `[...]` содержат список, а каждая запись в фигурных скобках `{...}` описывает одного пользователя:

```json
{
  "id": 1,
  "name": "Анна Волкова",
  "email": "anna.volkova@example.com"
}
```

`id` — уникальный номер пользователя, `name` — имя, `email` — адрес почты. Сохраняй эти поля: в следующих уроках будем использовать ту же структуру.

### 1.1. Добавь страницу пользователей на Python

Сохрани калькулятор по адресу `/`, а по `/users` сделай страницу «Пользователи». Внутри `do_GET` проверь `self.path` через `if` и выбери нужную страницу. Обе страницы должен обслуживать один запущенный `server.py`.

Для страницы `/users` прочитай `users.json` и сформируй HTML-список: один общий `<ul>`, внутри — отдельный `<li>` для каждого пользователя. В каждом пункте выведи имя и почту.

Начало списка должно выглядеть так:

```html
<ul>
    <li>Анна Волкова — anna.volkova@example.com</li>
    <li>Марк Соколов — mark.sokolov@example.com</li>
</ul>
```

Не переписывай пользователей вручную в код. Прочитай файл модулем `json` и пройди по полученному списку циклом. Для открытия русского текста укажи `encoding="utf-8"`. Значения записи доступны по ключам: `user["name"]`, `user["email"]`.

При вставке данных в HTML используй `html.escape`: она превращает специальные символы вроде `<` в текст, чтобы имя пользователя не стало частью разметки.

Добавь ссылку `<a href="/users">Пользователи</a>` на страницу калькулятора, а на страницу пользователей — `<a href="/">Калькулятор</a>`. Тег `<a>` задаёт ссылку, а `href` — адрес перехода.

Запусти `python server.py`, открой `/` и перейди по ссылке на `/users`. Проверь переход обратно. В списке должны быть все 20 пользователей, включая последнего — Глеба Фомина.

Не останавливая сервер, измени имя одного пользователя в JSON, сохрани файл и обнови страницу. Новое имя должно появиться без перезапуска: файл с данными читается при каждом обращении. Затем верни исходное имя и останови Python.

### 1.2. Выведи тот же список на PHP

Оставь калькулятор в `index.php`, а для списка создай рядом файл `users.php`. Сделай в нём такую же страницу из того же `users.json`. Прочитай файл через `file_get_contents(__DIR__ . '/users.json')`, а JSON преобразуй в массив через `json_decode` с параметром `true`. Затем выведи пользователей циклом `foreach`.

Общий `<ul>` и закрывающий `</ul>` напиши прямо в HTML. В цикле повторяй только `<li>` с именем и почтой. Всю страницу в строку собирать не нужно.

Для вывода имени и почты используй `htmlspecialchars`: в PHP она позволяет вывести специальные символы как текст, а не HTML-разметку.

Добавь ссылки между `/index.php` и `/users.php`. Запусти `php -S 127.0.0.1:8000`, открой `/index.php` и перейди на `/users.php`, затем обратно. Проверь, что список совпадает с Python-версией. Измени имя в JSON, сохрани и обнови страницу: изменение должно появиться и здесь. Верни исходное имя и останови PHP.

Объясни, кто выбирает страницу в каждом варианте: в Python путь проверяет наш код, а в этом запуске PHP встроенный сервер выбирает файл по адресу.

Сравни решения: данные хранятся отдельно от кода и подходят обоим языкам, а способы чтения файла и формирования HTML различаются. В исходном коде ответа браузера должен быть готовый список `<ul>` с 20 элементами `<li>`.
