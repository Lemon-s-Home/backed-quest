# 02. Сохранение данных на сервере

Рассмотрим кратко, как сайт принимает данные из формы и сохраняет их на сервере. Добавим имя и почту пользователя в `users.json`, откроем обновлённый список и проверим, что запись переживает перезапуск программы.

Сначала пройдём весь путь на Python, затем повторим на PHP. Пароли и проверки безопасности добавим в следующем уроке; вход — после них. Сейчас создаём запись о пользователе, а не учётную запись для входа.

## 1. Подготовь файлы

Останови сервер из первого урока через `Ctrl+C`. В папке `first-site` создай папку `lesson-02`, а внутри неё — `public`. Скопируй `users.json` из первого урока в `lesson-02`. Старые программы оставь: новый пример будем собирать отдельно.

Получится такая структура:

```text
first-site/
    lesson-02/
        users.json
        public/
```

Если JSON ещё не скачан, возьми [готовый users.json](./users.json). В PowerShell перейди в `lesson-02`. Все команды запуска в этом уроке выполняй из этой папки.

`public` — папка для файлов, доступных через веб-сервер. JSON положили рядом с ней, а не внутрь: программе нужен доступ к данным на диске, посетителю — только к страницам. Позже PHP будем запускать так, чтобы он раздавал файлы только из `public`.

## 2. Выбери страницу по маршруту

В первом уроке мы уже выбирали страницу по адресу. Такой выбор называют роутингом, а правило выбора — маршрутом.

У нашего сайта будет три маршрута:

| Метод и путь | Действие |
|---|---|
| `GET /users` | Показать пользователей |
| `GET /register` | Показать форму |
| `POST /register` | Принять форму и сохранить пользователя |

`GET` запрашивает содержимое. `POST` отправляет данные для обработки. Метод — часть запроса, а не адреса: в последних двух строках путь одинаковый, но действия разные.

Переход по ссылке и ввод адреса в браузере отправляют `GET`. Для отправки `POST` сделаем форму.

## 3. Покажи список и форму на Python

Создай в `lesson-02` файл `server.py`. Вставь:

```python
import json
from html import escape
from http.server import BaseHTTPRequestHandler, HTTPServer
from pathlib import Path
from urllib.parse import parse_qs, urlsplit


USERS_FILE = Path(__file__).with_name("users.json")
FORM = """
<h1>Добавить пользователя</h1>
<form action="/register" method="post">
    <p><label>Имя: <input name="name" required></label></p>
    <p><label>Почта: <input name="email" type="email" required></label></p>
    <button type="submit">Сохранить</button>
</form>
"""


def read_users():
    return json.loads(USERS_FILE.read_text(encoding="utf-8"))


class Page(BaseHTTPRequestHandler):
    def do_GET(self):
        path = urlsplit(self.path).path
        if path == "/users":
            items = "".join(
                f"<li>{escape(user['name'])} — {escape(user['email'])}</li>"
                for user in read_users()
            )
            self.reply(200, f"<h1>Пользователи</h1><ul>{items}</ul>")
        elif path == "/register":
            self.reply(200, FORM)
        else:
            self.reply(404, "<h1>Страница не найдена</h1>")

    def reply(self, status, content):
        html = f"""<!doctype html>
<html lang="ru">
<head><meta charset="utf-8"><title>Пользователи</title></head>
<body>
    <nav><a href="/users">Пользователи</a> | <a href="/register">Добавить</a></nav>
    {content}
</body>
</html>"""
        body = html.encode("utf-8")
        self.send_response(status)
        self.send_header("Content-Type", "text/html; charset=utf-8")
        self.send_header("Content-Length", str(len(body)))
        self.end_headers()
        self.wfile.write(body)


HTTPServer(("127.0.0.1", 8000), Page).serve_forever()
```

Запусти:

```powershell
python server.py
```

Открой `http://127.0.0.1:8000/users`, затем перейди по ссылке «Добавить». На `/register` должна появиться форма. Открой `/missing`: получишь нашу страницу «Страница не найдена» со статусом `404`. Сам адрес `/` мы пока тоже не обслуживаем.

### Разбери выбор страницы

`urlsplit(self.path).path` выделяет путь без параметров после `?`. В `do_GET` мы сравниваем его со знакомыми строками и выбираем содержимое. Метод `reply` оформляет общий HTML и отправляет ответ — эти строки больше не надо повторять в каждом маршруте.

`read_users()` читает JSON с диска и превращает его в список Python. `Path(__file__).with_name("users.json")` находит файл рядом с `server.py`, независимо от текущей папки терминала.

В выражении `"".join(...)` мы собираем строки `<li>` для всех записей в одну строку. `escape` позволяет вывести имена и почту как текст внутри HTML.

### Разбери форму

В `<form>` два важных атрибута:

- `action="/register"` — куда отправить данные;
- `method="post"` — каким методом их отправить.

У каждого `<input>` есть `name`. Это имя поля в отправляемых данных: сервер получит `name` и `email`. Текст «Имя» внутри `<label>` — подпись для человека, он не заменяет атрибут `name`.

`required` просит браузер не отправлять пустое поле. `type="email"` включает браузерную проверку формата почты. Эти проверки удобны посетителю, но серверу нужны собственные проверки: запрос может прийти и без этой формы.

Заполни имя и почту и нажми «Сохранить». Пока получишь `501`: мы написали `do_GET`, но ещё не добавили `do_POST`. Одного существования страницы `/register` недостаточно для приёма отправленных данных.

## 4. Прими и сохрани данные на Python

Останови сервер. Внутри класса `Page`, перед методом `reply`, добавь метод с таким же отступом, как у `do_GET`:

```python
    def do_POST(self):
        if urlsplit(self.path).path != "/register":
            self.reply(404, "<h1>Страница не найдена</h1>")
            return

        length = int(self.headers.get("Content-Length", "0"))
        body = self.rfile.read(length).decode("utf-8")
        fields = parse_qs(body, keep_blank_values=True)
        name = fields.get("name", [""])[0].strip()
        email = fields.get("email", [""])[0].strip()

        if not name or not email:
            self.reply(400, "<h1>Заполни имя и почту</h1>" + FORM)
            return
        if "@" not in email or any(char.isspace() for char in email):
            self.reply(400, "<h1>Проверь адрес почты</h1>" + FORM)
            return

        users = read_users()
        next_id = max((user["id"] for user in users), default=0) + 1
        users.append({"id": next_id, "name": name, "email": email})
        USERS_FILE.write_text(
            json.dumps(users, ensure_ascii=False, indent=2) + "\n",
            encoding="utf-8",
        )

        self.send_response(303)
        self.send_header("Location", "/users")
        self.send_header("Content-Length", "0")
        self.end_headers()
```

Сохрани и снова запусти `python server.py`. Открой `/register`, введи `Лена Котова` и `lena.kotova@example.com`, нажми «Сохранить».

Браузер должен открыть `/users`, а в конце списка появится новая запись. Открой `users.json` в редакторе: имя и почта должны быть и там. Если редактор предлагает перечитать изменённый файл, согласись.

### Что произошло при отправке

1. Браузер отправил `POST /register`. Поля находятся в теле запроса.
2. Библиотека вызвала `do_POST`. Мы прочитали тело через `self.rfile`.
3. `parse_qs` разобрал данные формы в словарь. Значения в нём — списки, поэтому `[0]` выбирает первое значение поля. Если поля нет, `.get(..., [""])` даёт пустую строку.
4. `strip()` убрал пробелы по краям. Затем условия проверили данные. При ошибке ответили `400` и вышли через `return`, не меняя файл.
5. Мы прочитали прежних пользователей, добавили запись и записали весь обновлённый список на диск.
6. Ответ `303` с заголовком `Location: /users` предложил браузеру открыть список отдельным запросом `GET`.

Проверка почты здесь намеренно простая: она отсеивает часть очевидных ошибок, но не проверяет все допустимые форматы и не доказывает существование адреса. Надёжность проверок подробно разберём в следующем уроке.

### Посмотри на запрос

Открой инструменты разработчика (`F12`), вкладку «Сеть» (`Network`), включи сохранение журнала (`Preserve log`). Добавь ещё одного вымышленного пользователя.

Найди `POST /register`. Во вкладке с отправленными данными (`Payload`) увидишь поля `name` и `email`. У ответа статус `303`, а за ним идёт `GET /users` со статусом `200`.

Серверное чтение тела и разбор формы в Python описаны в [документации `parse_qs`](https://docs.python.org/3/library/urllib.parse.html#urllib.parse.parse_qs).

### Проверь сохранение

Обнови список несколько раз. Новые пользователи не должны добавляться: обновляется страница, полученная через `GET`, а не повторяется отправка формы.

Теперь останови сервер и запусти его снова. Открой `/users`: добавленные записи должны остаться. Переменные завершённой программы исчезли, но файл сохранился на диске. При новом запросе программа снова прочитала его.

Затем открой форму и введи в имя только пробелы, а в почту — корректный адрес. Браузер может пропустить такое имя, но после `strip()` сервер получит пустую строку и вернёт `400`. Проверь: новая запись в JSON не появилась.

Закончи проверку и останови Python.

## 5. Повтори на PHP

Теперь используем тот же `users.json`: уже добавленные записи должны сохраниться. Создай в папке `public` файл `index.php` и вставь:

```php
<?php

$usersFile = dirname(__DIR__) . '/users.json';
$path = parse_url($_SERVER['REQUEST_URI'], PHP_URL_PATH);
$method = $_SERVER['REQUEST_METHOD'];
$error = '';

if (!in_array($path, ['/users', '/register'], true)) {
    http_response_code(404);
    exit('Страница не найдена');
}

if ($method === 'POST' && $path === '/register') {
    $name = trim($_POST['name'] ?? '');
    $email = trim($_POST['email'] ?? '');

    if ($name === '' || $email === '') {
        $error = 'Заполни имя и почту';
    } elseif (!filter_var($email, FILTER_VALIDATE_EMAIL)) {
        $error = 'Проверь адрес почты';
    }

    if ($error === '') {
        $users = json_decode(file_get_contents($usersFile), true, 512, JSON_THROW_ON_ERROR);
        $ids = array_column($users, 'id');
        $nextId = $ids === [] ? 1 : max($ids) + 1;
        $users[] = ['id' => $nextId, 'name' => $name, 'email' => $email];
        $json = json_encode($users, JSON_UNESCAPED_UNICODE | JSON_PRETTY_PRINT | JSON_THROW_ON_ERROR);
        if (file_put_contents($usersFile, $json . "\n") === false) {
            throw new RuntimeException('Не удалось сохранить пользователей');
        }
        header('Location: /users', true, 303);
        exit;
    }
    http_response_code(400);
} elseif ($method !== 'GET') {
    http_response_code(405);
    header('Allow: ' . ($path === '/register' ? 'GET, POST' : 'GET'));
    exit('Метод не поддерживается для этой страницы');
}

$users = $path === '/users'
    ? json_decode(file_get_contents($usersFile), true, 512, JSON_THROW_ON_ERROR)
    : [];
header('Content-Type: text/html; charset=utf-8');
?>
<!doctype html>
<html lang="ru">
<head><meta charset="utf-8"><title>Пользователи</title></head>
<body>
    <nav><a href="/users">Пользователи</a> | <a href="/register">Добавить</a></nav>
    <?php if ($path === '/users'): ?>
        <h1>Пользователи</h1>
        <ul>
            <?php foreach ($users as $user): ?>
                <li><?= htmlspecialchars($user['name'], ENT_QUOTES, 'UTF-8') ?> — <?= htmlspecialchars($user['email'], ENT_QUOTES, 'UTF-8') ?></li>
            <?php endforeach; ?>
        </ul>
    <?php else: ?>
        <h1>Добавить пользователя</h1>
        <?php if ($error !== ''): ?>
            <p><?= htmlspecialchars($error, ENT_QUOTES, 'UTF-8') ?></p>
        <?php endif; ?>
        <form action="/register" method="post">
            <p><label>Имя: <input name="name" required></label></p>
            <p><label>Почта: <input name="email" type="email" required></label></p>
            <button type="submit">Сохранить</button>
        </form>
    <?php endif; ?>
</body>
</html>
```

Сохрани файл в UTF-8. Из папки `lesson-02` запусти:

```powershell
php -S 127.0.0.1:8000 -t public public/index.php
```

`-t public` задаёт папку доступных файлов. Последний аргумент `public/index.php` назначает файл обработки обращений: встроенный сервер выполняет его и для `/users`, и для `/register`. Теперь выбор страницы делает наш код, а не имя PHP-файла в адресе.

Открой `http://127.0.0.1:8000/users`. Записи, добавленные через Python, должны быть на месте. Перейди в форму, добавь пользователя, проверь список и JSON, затем перезапусти PHP и убедись, что запись осталась.

### Разбери маршруты и форму

`$_SERVER['REQUEST_URI']` содержит адрес обращения, а `$_SERVER['REQUEST_METHOD']` — метод. Мы выделяем путь и сопоставляем его с методом, как в таблице в начале урока.

PHP сам разбирает тело обычной HTML-формы и предоставляет поля в массиве `$_POST`. Поэтому здесь не нужны чтение `rfile` и вызов `parse_qs`. Выражение `$_POST['name'] ?? ''` берёт имя, а при отсутствии поля возвращает пустую строку. `trim` убирает пробелы по краям.

`filter_var` с `FILTER_VALIDATE_EMAIL` проверяет формат почты. В Python-примере была наша простая проверка, здесь — готовая функция. Обе проверки не подтверждают, что почта существует или принадлежит посетителю.

Если метод не поддерживается для выбранного пути, код отвечает `405`. Например, для `/users` мы предусмотрели только `GET`. `Allow` перечисляет разрешённые методы. Для несуществующего пути возвращается `404`.

### Разбери запись и вывод

`dirname(__DIR__)` находит родительскую папку для `public`, поэтому JSON читается из `lesson-02`, а не из папки доступных страниц.

`json_decode(..., true)` превращает JSON в массив. `array_column($users, 'id')` собирает номера, а `max` помогает получить следующий. Если список пуст, начинаем с 1. Прибавление к максимальному номеру надёжнее, чем прибавление к количеству записей: часть записей в будущем могут удалить.

`json_encode` превращает обновлённый массив обратно в JSON, `file_put_contents` записывает его в файл. Параметры `JSON_THROW_ON_ERROR` заставляют PHP сообщить об ошибке преобразования вместо продолжения с испорченными данными. Ошибку записи мы тоже проверяем.

После записи `header('Location: /users', true, 303)` отправляет перенаправление, а `exit` завершает обработку. Заголовки отправляются до HTML — поэтому обработка формы находится в начале файла.

Ниже остаётся обычная HTML-разметка. Конструкции `if ... endif` выбирают часть страницы, а `foreach ... endforeach` повторяет `<li>` для каждого пользователя. HTML не пришлось собирать в строку.

Повтори проверку с пробелами в имени. Убедись, что сервер отвечает `400`, файл не меняется, а после исправления имени пользователь добавляется. Проверь `POST`, `303` и последующий `GET` во вкладке «Сеть». Затем останови PHP.

Подробнее: [данные формы в PHP](https://www.php.net/manual/en/reserved.variables.post.php), [HTML-форма](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/form), [ответ `303`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Status/303).

## 6. Сравни, где находятся данные

| Этап | Где данные |
|---|---|
| Ввод имени и почты | В полях формы в браузере |
| Отправка | В теле `POST`-запроса |
| Обработка | В переменных программы на сервере |
| Сохранение | В `users.json` на диске сервера |
| Открытие списка | В HTML-ответе, сформированном из JSON |

Сами переменные не заменяют сохранение. Вызов `append` в Python или `$users[] = ...` в PHP меняет список в памяти. На диск он попадёт только после записи файла.

При обновлении списка сервер читает JSON заново. В браузер отправляется HTML, а не файл базы пользователей целиком. Попробуй открыть `/users.json`: оба наших примера вернут `404`.

У нас одна учебная программа, которая последовательно обрабатывает запросы. JSON удобен, чтобы увидеть чтение и запись своими глазами. Но операция «прочитать, изменить, записать» не становится общей безопасной транзакцией сама по себе: два независимых процесса могут прочитать одну старую версию и затереть изменения друг друга. Когда перейдём к совместной работе нескольких обработчиков, понадобятся другие гарантии хранения.

## Шпаргалка

- Маршрут сопоставляет метод и путь с действием приложения.
- `GET /register` показывает форму, `POST /register` обрабатывает её.
- `action` задаёт адрес отправки формы, `method` — метод, `name` — ключ поля.
- Python разбирает форму через `parse_qs`, PHP предоставляет обычные поля в `$_POST`.
- Сначала проверяем данные, затем меняем файл. При ошибке проверки возвращаем `400`.
- Данные в памяти и данные на диске — разные вещи.
- После сохранения `303` переводит браузер на `GET /users`.
- JSON лежит вне `public`; код читает его по пути на диске.

## Напоследок

1. JSON происходит от записи объектов в JavaScript, но стал независимым форматом. Поэтому наши программы на Python и PHP без переделки читают один файл. JSON стандартизован также как ECMA-404. [История и описание формата](https://www.json.org/json-en.html).

2. Кнопка «Сохранить» не умеет записывать файл на сервере. Она запускает отправку формы. Всё остальное делает наш обработчик — поэтому одинаковая HTML-форма работает с обоими языками. [Как работает форма](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/form).

3. Приём «после POST перенаправить на GET» называют Post/Redirect/Get. Он позволяет обновлять страницу результата без повторного добавления записи. Но от двух отдельных нажатий на отправку он не защищает: проверку повторной регистрации добавим позже. [Назначение `303 See Other`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Status/303).

## Практика

### 2.1. Добавь город пользователя

Добавь в форму поле «Город» с именем `city`, сохрани его в JSON и выведи рядом с именем и почтой в списке. Сделай это сначала на Python, затем на PHP.

У старых записей поля `city` нет: вместо ошибки показывай «Город не указан». Проверь на старом пользователе и на новом. Добавленная через Python запись должна правильно отображаться через PHP и наоборот.

### 2.2. Верни введённое имя после ошибки

Сейчас после ошибки форма пустая. Измени оба примера так, чтобы при отклонении данных введённые имя и почта оставались в полях: пользователь исправит только ошибку.

Для этого подставь значения в атрибут `value` у `<input>`. Используй `escape` в Python и `htmlspecialchars` в PHP, как при выводе списка.

Проверь: имя с кавычкой сохраняется в поле целиком, исправление ошибки добавляет одну запись, а сама неуспешная отправка не меняет JSON.
