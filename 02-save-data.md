# 02. Сохранение данных на сервере

Рассмотрим кратко, как сайт принимает данные из формы и сохраняет их на сервере. Добавим имя и почту пользователя в `users.json`, откроем обновлённый список и проверим, что запись переживает перезапуск программы.

Пример выполним на PHP. Выводы о запросах и хранении данных применимы к другим языкам бэкенда. Пароли и проверки безопасности добавим в следующем уроке; вход — после них. Сейчас создаём запись о пользователе, а не учётную запись для входа.

## 1. Подготовь файлы

Останови сервер из первого урока через `Ctrl+C`. В папке `first-site` создай папку `lesson-02`, а внутри неё — `public`. Скопируй `users.json` из первого урока в `lesson-02`. Старые программы оставь: новый пример будем собирать отдельно.

Получится такая структура:

```text
first-site/
    lesson-02/
        users.json
        public/
```

Если JSON ещё не скачан, возьми [готовый users.json](./users.json). В PowerShell перейди в `lesson-02`. Все команды запуска в этом уроке выполняй из этой папки.

`public` — папка для файлов, доступных через веб-сервер. JSON положили рядом с ней, а не внутрь: программе нужен доступ к данным на диске, посетителю — только к страницам. Позже PHP будем запускать так, чтобы он раздавал файлы только из `public`.

## 2. Выбери страницу по маршруту

В первом уроке мы уже выбирали страницу по адресу. Такой выбор называют роутингом, а правило выбора — маршрутом.

У нашего сайта будет три маршрута:

| Метод и путь | Действие |
|---|---|
| `GET /users` | Показать пользователей |
| `GET /register` | Показать форму |
| `POST /register` | Принять форму и сохранить пользователя |

`GET` запрашивает содержимое. `POST` отправляет данные для обработки. Метод — часть запроса, а не адреса: в последних двух строках путь одинаковый, но действия разные.

Переход по ссылке и ввод адреса в браузере отправляют `GET`. Для отправки `POST` сделаем форму.

## 3. Покажи форму и сохрани данные

Создай в папке `public` файл `index.php` и вставь:

```php
<?php

$usersFile = dirname(__DIR__) . '/users.json';
$path = parse_url($_SERVER['REQUEST_URI'], PHP_URL_PATH);
$method = $_SERVER['REQUEST_METHOD'];
$error = '';

if (!in_array($path, ['/users', '/register'], true)) {
    http_response_code(404);
    exit('Страница не найдена');
}

if ($method === 'POST' && $path === '/register') {
    $name = trim($_POST['name'] ?? '');
    $email = trim($_POST['email'] ?? '');

    if ($name === '' || $email === '') {
        $error = 'Заполни имя и почту';
    } elseif (!filter_var($email, FILTER_VALIDATE_EMAIL)) {
        $error = 'Проверь адрес почты';
    }

    if ($error === '') {
        $users = json_decode(file_get_contents($usersFile), true, 512, JSON_THROW_ON_ERROR);
        $ids = array_column($users, 'id');
        $nextId = $ids === [] ? 1 : max($ids) + 1;
        $users[] = ['id' => $nextId, 'name' => $name, 'email' => $email];
        $json = json_encode($users, JSON_UNESCAPED_UNICODE | JSON_PRETTY_PRINT | JSON_THROW_ON_ERROR);
        if (file_put_contents($usersFile, $json . "\n") === false) {
            throw new RuntimeException('Не удалось сохранить пользователей');
        }
        header('Location: /users', true, 303);
        exit;
    }
    http_response_code(400);
} elseif ($method !== 'GET') {
    http_response_code(405);
    header('Allow: ' . ($path === '/register' ? 'GET, POST' : 'GET'));
    exit('Метод не поддерживается для этой страницы');
}

$users = $path === '/users'
    ? json_decode(file_get_contents($usersFile), true, 512, JSON_THROW_ON_ERROR)
    : [];
header('Content-Type: text/html; charset=utf-8');
?>
<!doctype html>
<html lang="ru">
<head><meta charset="utf-8"><title>Пользователи</title></head>
<body>
    <nav><a href="/users">Пользователи</a> | <a href="/register">Добавить</a></nav>
    <?php if ($path === '/users'): ?>
        <h1>Пользователи</h1>
        <ul>
            <?php foreach ($users as $user): ?>
                <li><?= htmlspecialchars($user['name'], ENT_QUOTES, 'UTF-8') ?> — <?= htmlspecialchars($user['email'], ENT_QUOTES, 'UTF-8') ?></li>
            <?php endforeach; ?>
        </ul>
    <?php else: ?>
        <h1>Добавить пользователя</h1>
        <?php if ($error !== ''): ?>
            <p><?= htmlspecialchars($error, ENT_QUOTES, 'UTF-8') ?></p>
        <?php endif; ?>
        <form action="/register" method="post">
            <p><label>Имя: <input name="name" required></label></p>
            <p><label>Почта: <input name="email" type="email" required></label></p>
            <button type="submit">Сохранить</button>
        </form>
    <?php endif; ?>
</body>
</html>
```

Сохрани файл в UTF-8. Из папки `lesson-02` запусти:

```powershell
php -S 127.0.0.1:8000 -t public public/index.php
```

`-t public` задаёт папку доступных файлов. Последний аргумент `public/index.php` назначает файл обработки обращений: встроенный сервер выполняет его и для `/users`, и для `/register`. Теперь выбор страницы делает наш код, а не имя PHP-файла в адресе.

Открой `http://127.0.0.1:8000/users`. Ты увидишь пользователей из JSON. Перейди в форму, добавь пользователя, проверь список и JSON, затем перезапусти PHP и убедись, что запись осталась.

### Разбери маршруты и форму

`$_SERVER['REQUEST_URI']` содержит адрес обращения, а `$_SERVER['REQUEST_METHOD']` — метод. Мы выделяем путь и сопоставляем его с методом, как в таблице в начале урока.

PHP сам разбирает тело обычной HTML-формы и предоставляет поля в массиве `$_POST`. Выражение `$_POST['name'] ?? ''` берёт имя, а при отсутствии поля возвращает пустую строку. `trim` убирает пробелы по краям.

`filter_var` с `FILTER_VALIDATE_EMAIL` проверяет формат почты. Эта проверка не подтверждает, что почта существует или принадлежит посетителю.

Если метод не поддерживается для выбранного пути, код отвечает `405`. Например, для `/users` мы предусмотрели только `GET`. `Allow` перечисляет разрешённые методы. Для несуществующего пути возвращается `404`.

### Разбери запись и вывод

`dirname(__DIR__)` находит родительскую папку для `public`, поэтому JSON читается из `lesson-02`, а не из папки доступных страниц.

`json_decode(..., true)` превращает JSON в массив. `array_column($users, 'id')` собирает номера, а `max` помогает получить следующий. Если список пуст, начинаем с 1. Прибавление к максимальному номеру надёжнее, чем прибавление к количеству записей: часть записей в будущем могут удалить.

`json_encode` превращает обновлённый массив обратно в JSON, `file_put_contents` записывает его в файл. Параметры `JSON_THROW_ON_ERROR` заставляют PHP сообщить об ошибке преобразования вместо продолжения с испорченными данными. Ошибку записи мы тоже проверяем.

После записи `header('Location: /users', true, 303)` отправляет перенаправление, а `exit` завершает обработку. Заголовки отправляются до HTML — поэтому обработка формы находится в начале файла.

`htmlspecialchars` при выводе имени и почты превращает специальные символы в текст: имя не должно становиться HTML-разметкой.

Ниже остаётся обычная HTML-разметка. Конструкции `if ... endif` выбирают часть страницы, а `foreach ... endforeach` повторяет `<li>` для каждого пользователя. HTML не пришлось собирать в строку.

Введи в имя только пробелы, а в почту — корректный адрес. Убедись, что сервер отвечает `400`, файл не меняется, а после исправления имени пользователь добавляется. Нажми `F12`, открой вкладку «Сеть» (`Network`) и включи сохранение журнала (`Preserve log`). Отправь форму с корректными данными. Найди `POST /register`: в разделе `Payload` будут имя и почта. За ответом `303` следует `GET /users` со статусом `200`. Обнови список несколько раз: новые записи не должны появляться. Затем останови PHP.

Подробнее: [данные формы в PHP](https://www.php.net/manual/en/reserved.variables.post.php), [HTML-форма](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/form), [ответ `303`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Status/303).

## 4. Сравни, где находятся данные

| Этап | Где данные |
|---|---|
| Ввод имени и почты | В полях формы в браузере |
| Отправка | В теле `POST`-запроса |
| Обработка | В переменных программы на сервере |
| Сохранение | В `users.json` на диске сервера |
| Открытие списка | В HTML-ответе, сформированном из JSON |

Сами переменные не заменяют сохранение. Выражение `$users[] = ...` меняет список в памяти. На диск он попадёт только после записи файла.

При обновлении списка сервер читает JSON заново. В браузер отправляется HTML, а не файл базы пользователей целиком. Попробуй открыть `/users.json`: сервер вернёт `404`.

У нас одна учебная программа, которая последовательно обрабатывает запросы. JSON удобен, чтобы увидеть чтение и запись своими глазами. Но операция «прочитать, изменить, записать» не становится общей безопасной транзакцией сама по себе: два независимых процесса могут прочитать одну старую версию и затереть изменения друг друга. Когда перейдём к совместной работе нескольких обработчиков, понадобятся другие гарантии хранения.

## Шпаргалка

- Маршрут сопоставляет метод и путь с действием приложения.
- `GET /register` показывает форму, `POST /register` обрабатывает её.
- `action` задаёт адрес отправки формы, `method` — метод, `name` — ключ поля.
- В PHP поля обычной формы доступны в `$_POST`; в любом языке серверу нужно получить и проверить присланные данные.
- Сначала проверяем данные, затем меняем файл. При ошибке проверки возвращаем `400`.
- Данные в памяти и данные на диске — разные вещи.
- После сохранения `303` переводит браузер на `GET /users`.
- JSON лежит вне `public`; код читает его по пути на диске.

## Напоследок

1. JSON происходит от записи объектов в JavaScript, но стал независимым форматом. Его могут читать программы на разных языках. JSON стандартизован также как ECMA-404. [История и описание формата](https://www.json.org/json-en.html).

2. Кнопка «Сохранить» не умеет записывать файл на сервере. Она запускает отправку формы. Всё остальное делает наш обработчик — поэтому одинаковая HTML-форма может отправлять данные обработчику на любом языке. [Как работает форма](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/form).

3. Приём «после POST перенаправить на GET» называют Post/Redirect/Get. Он позволяет обновлять страницу результата без повторного добавления записи. Но от двух отдельных нажатий на отправку он не защищает: проверку повторной регистрации добавим позже. [Назначение `303 See Other`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Status/303).

## Практика

### 2.1. Добавь город пользователя

Добавь в форму поле «Город» с именем `city`, сохрани его в JSON и выведи рядом с именем и почтой в списке.

У старых записей поля `city` нет: вместо ошибки показывай «Город не указан». Проверь на старом пользователе и на новом.

### 2.2. Верни введённое имя после ошибки

Сейчас после ошибки форма пустая. Измени пример так, чтобы при отклонении данных введённые имя и почта оставались в полях: пользователь исправит только ошибку.

Для этого подставь значения в атрибут `value` у `<input>`. Используй `htmlspecialchars`, как при выводе списка.

Проверь: имя с кавычкой сохраняется в поле целиком, исправление ошибки добавляет одну запись, а сама неуспешная отправка не меняет JSON.
