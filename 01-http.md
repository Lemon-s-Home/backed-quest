# 01. Клиент и сервер: как говорит HTTP

Любой сайт — это два собеседника, которые вежливо перебрасываются текстом. Один спрашивает, другой отвечает. Язык, на котором они говорят, называется HTTP, и он сильно проще, чем кажется.

Код сайта за тебя напишет агент. А вот понять, почему форма «молчит» или вход «не работает», придётся самому. Для этого надо знать, что именно полетело по проводу. Начнём с этого.

## Две роли

- Клиент спрашивает. Чаще всего это браузер, но бывает и `curl`, и мобильное приложение, и твой агент.
- Сервер отвечает. Это программа, которая сидит на каком-то адресе и порту и ждёт запросов.

Клиент всегда говорит первым. Сервер сам ничего не присылает, он только отвечает.

## Запрос

Запрос — это обычный текст:

```text
GET /hello HTTP/1.1
Host: localhost:8000
```

В нём три части:

- метод (`GET`) — что хотим сделать;
- путь (`/hello`) — над чем;
- заголовки (`Host: ...`) — дополнительные сведения.

## Ответ

Ответ тоже текст:

```text
HTTP/1.1 200 OK
Content-Type: text/plain; charset=utf-8

Привет
```

В нём:

- строка статуса: версия, код (`200`) и пояснение (`OK`);
- заголовки;
- пустая строка;
- тело — то, что показывает браузер.

## Коды статуса

По первой цифре кода видно, как всё прошло:

| Код | Смысл | Пример |
|-----|-------|--------|
| 2xx | всё хорошо | `200 OK` |
| 3xx | иди в другое место | `302 Found` (редирект) |
| 4xx | ошибка клиента | `404 Not Found`, `403 Forbidden` |
| 5xx | ошибка сервера | `500 Internal Server Error` |

Дальше каждый код найдёт своё место: `404` для чужого адреса, `302` после входа, `403` для закрытой страницы.

## curl: клиент без браузера

`curl -i` печатает ответ целиком, вместе со статусом и заголовками. `curl -v` показывает ещё и сам запрос.

```bash
curl -i http://127.0.0.1:8000/
```

Привыкай читать то, что видишь. Так находят причину ошибок: не гадают, а смотрят, что на самом деле ответил сервер.

## Свой первый сервер

Один и тот же сервер на двух языках. На любой запрос он отвечает приветствием.

PHP, файл `index.php`:

```php
<?php

declare(strict_types=1);

header('Content-Type: text/plain; charset=utf-8');
echo "Привет из PHP\n";
```

Запуск встроенным сервером PHP:

```bash
php -S 127.0.0.1:8000
```

Python, файл `server.py`:

```python
from http.server import BaseHTTPRequestHandler, HTTPServer


class Handler(BaseHTTPRequestHandler):
    def do_GET(self) -> None:
        body = "Привет из Python\n".encode("utf-8")
        self.send_response(200)
        self.send_header("Content-Type", "text/plain; charset=utf-8")
        self.send_header("Content-Length", str(len(body)))
        self.end_headers()
        self.wfile.write(body)


HTTPServer(("127.0.0.1", 8001), Handler).serve_forever()
```

Запуск:

```bash
python3 server.py
```

Проверка в другом окне терминала:

```bash
curl -i http://127.0.0.1:8000/
curl -i http://127.0.0.1:8001/
```

## Что общего, а что нет

Общее, то есть принцип:

- сервер слушает адрес и порт;
- на запрос приходит ответ со статусом, заголовками и телом;
- без заголовка `Content-Type` клиент не знает, как показывать тело.

Различия, то есть особенности языка:

- PHP сам разбирает запрос и на каждый запрос запускает `index.php`. Статус и часть заголовков он ставит сам, ты пишешь только «что ответить».
- В Python ты пишешь класс-обработчик и вручную собираешь ответ: статус, заголовки, тело. Зато видно, из чего ответ состоит.
- Сервер Python из стандартной библиотеки отвечает по `HTTP/1.0`, PHP — по `HTTP/1.1`. Для нас это не важно, но в ответе видно.

Ручная сборка ответа — это та рутина, которую потом прячут фреймворки.

## Шпаргалка

- Клиент спрашивает, сервер отвечает. Всегда в таком порядке.
- Запрос: метод, путь, заголовки.
- Ответ: статус, заголовки, пустая строка, тело.
- `2xx` — хорошо, `3xx` — перенаправление, `4xx` — ошибка клиента, `5xx` — ошибка сервера.
- `curl -i` показывает ответ, `curl -v` — запрос и ответ.
- `127.0.0.1` — твой собственный компьютер, `8000` — порт.

## Напоследок

1. HTTP/3 уже не ездит по TCP. Он работает поверх QUIC, а тот — поверх UDP. По данным W3Techs, на июль 2026 года его поддерживает около 40% сайтов. При этом доля реальных запросов заметно меньше: Cloudflare Radar показывал для первого квартала 2026 года около 21%. Старые версии никуда не делись, и одни и те же `GET` и `404` работают во всех.

2. По оценкам Cloudflare Radar за 2026 год, больше половины запросов к HTML-страницам делают не люди, а боты и агенты. Значит, ты не только клиент своего сервера: тот, кто читает твой сайт, всё чаще программа. Для неё важны те же вещи, что для тебя: ясный статус и внятный ответ.

3. Все версии HTTP описаны общими правилами. В июне 2022 года вышел RFC 9110 «HTTP Semantics». В нём собрано то, что одинаково для любой версии: методы, коды, заголовки. А RFC 9112, 9113 и 9114 описывают, как это едет по проводу в HTTP/1.1, HTTP/2 и HTTP/3. Поэтому курс учит смыслу запроса и ответа, а не версии.

## Практика

### 1.1. Найди три различия

Запусти оба сервера из урока: один на порту `8000`, другой на `8001`. Выполни `curl -i` к каждому и сравни ответы. Найди три различия в заголовках или строке статуса и запиши по одной фразе: что оно значит.

### 1.2. Поставь задачу агенту

Сформулируй агенту задачу: сервер отвечает `200` на путь `/` и `404` на любой другой путь. В задаче должно быть три части:

- исход: что должно получиться;
- ограничение: на каком языке и без чего (например, без сторонних пакетов);
- критерий готовности: какие команды `curl` ты выполнишь, чтобы принять работу.

Дай задачу агенту дважды: для PHP и для Python. Принимай работу только по своим `curl`, а не по отчёту агента.
