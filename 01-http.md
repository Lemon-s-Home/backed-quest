# 1. Клиент и сервер: как говорит HTTP

## Зачем это знать, если код пишет агент

Агент напишет сайт за минуты. Но когда страница не открывается, форма не отправляется или вход «не работает», разбираться придётся тебе. Для этого нужен язык, на котором общаются браузер и сервер. Это HTTP.

Без него просьба «сделай регистрацию» превращается в лотерею: ты не знаешь, что просить и что проверять.

## Две роли

- Клиент — тот, кто спрашивает. Чаще всего браузер, но может быть `curl`, мобильное приложение или другая программа.
- Сервер — тот, кто отвечает. Это программа, которая сидит на каком-то адресе и порту и ждёт запросов.

Клиент всегда говорит первым. Сервер сам ничего не присылает: он только отвечает.

## Запрос и ответ

Весь разговор — текст. Запрос выглядит так:

```text
GET /hello HTTP/1.1
Host: localhost:8000
```

В нём три части:
- метод (`GET`) — что хотим сделать;
- путь (`/hello`) — над чем;
- заголовки (`Host: ...`) — дополнительные сведения.

Ответ тоже текст:

```text
HTTP/1.1 200 OK
Content-Type: text/plain; charset=utf-8

Привет
```

В нём:
- строка статуса: версия, код (`200`), пояснение (`OK`);
- заголовки;
- пустая строка;
- тело ответа — то, что показывает браузер.

## Коды статуса

Код — это первая цифра, по которой видно, как всё прошло:

| Код | Смысл | Пример |
|-----|-------|--------|
| 2xx | всё хорошо | `200 OK` |
| 3xx | иди в другое место | `302 Found` (редирект) |
| 4xx | ошибка клиента | `404 Not Found`, `403 Forbidden` |
| 5xx | ошибка сервера | `500 Internal Server Error` |

Позже каждый код найдёт своё место: `404` для чужого адреса, `302` после входа, `403` для закрытой страницы.

## Смотрим руками: curl

`curl` — клиент без браузера. Флаг `-i` показывает ответ целиком, вместе с заголовками:

```bash
curl -i http://127.0.0.1:8000/
```

Флаг `-v` показывает ещё и сам запрос. Привыкай читать то, что видишь: именно так находят причину ошибок.

## Свой первый сервер

Один и тот же сервер на двух языках. Он на любой запрос отвечает приветствием.

PHP, файл `index.php`:

```php
<?php

declare(strict_types=1);

header('Content-Type: text/plain; charset=utf-8');
echo "Привет из PHP\n";
```

Запуск встроенным веб-сервером PHP:

```bash
php -S 127.0.0.1:8000
```

Python, файл `server.py`:

```python
from http.server import BaseHTTPRequestHandler, HTTPServer


class Handler(BaseHTTPRequestHandler):
    def do_GET(self) -> None:
        body = "Привет из Python\n".encode("utf-8")
        self.send_response(200)
        self.send_header("Content-Type", "text/plain; charset=utf-8")
        self.send_header("Content-Length", str(len(body)))
        self.end_headers()
        self.wfile.write(body)


HTTPServer(("127.0.0.1", 8001), Handler).serve_forever()
```

Запуск:

```bash
python3 server.py
```

Проверка в другом окне терминала:

```bash
curl -i http://127.0.0.1:8000/
curl -i http://127.0.0.1:8001/
```

## Что общего, а что нет

Общее, то есть принцип:
- сервер слушает адрес и порт;
- на запрос приходит ответ со статусом, заголовками и телом;
- без заголовка `Content-Type` клиент не знает, как показывать тело.

Различия, то есть особенности языка:
- PHP сам разбирает запрос и вызывает `index.php` на каждый запрос. Статус и заголовки по умолчанию ставит сам. Ты пишешь только «что ответить».
- В Python ты пишешь класс-обработчик и сам явно собираешь ответ: статус, заголовки, тело. Зато видно, из чего ответ состоит.
- Python-сервер из стандартной библиотеки отвечает по `HTTP/1.0`, PHP — по `HTTP/1.1`. Для нас это не важно, но в ответе видно.

Ради этой разницы потом и существуют фреймворки: они прячут ручную сборку ответа.

## Шпаргалка

- Клиент спрашивает, сервер отвечает. Всегда в таком порядке.
- Запрос: метод, путь, заголовки.
- Ответ: статус, заголовки, пустая строка, тело.
- `2xx` — хорошо, `3xx` — перенаправление, `4xx` — ошибка клиента, `5xx` — ошибка сервера.
- `curl -i` показывает ответ, `curl -v` — запрос и ответ.
- Адрес `127.0.0.1` — твой собственный компьютер, `8000` — порт.

## Напоследок

1. HTTP придумал Тим Бернерс-Ли в начале 1990-х в ЦЕРНе. Первая версия, `HTTP/0.9`, умела один метод — `GET` — и отдавала только текст страницы, без заголовков и без кодов статуса.

2. Код `418 I'm a teapot` существует по-настоящему. Он появился в шуточной спецификации 1998 года про управление чайниками по сети и с тех пор кочует по серверам как пасхалка.

3. Слово «Referer» в заголовке `Referer` написано с ошибкой. Опечатка попала в спецификацию, её исправлять побоялись, и теперь она часть стандарта навсегда.

## Практика

### 1.1. Найди три различия

Запусти оба сервера из урока, один на порту `8000`, другой на `8001`. Выполни `curl -i` к каждому и сравни ответы. Найди три различия в заголовках или строке статуса и запиши по одной фразе: что это значит.

### 1.2. Поставь задачу агенту

Сформулируй агенту задачу: сервер должен отвечать `200` на путь `/` и `404` на любой другой путь. В задаче должно быть три части:
- исход: что должно получиться;
- ограничение: на каком языке и без чего (например, без сторонних пакетов);
- критерий готовности: какие команды `curl` ты выполнишь, чтобы принять работу.

Дай задачу агенту дважды: для PHP и для Python. Прими результат только по своим `curl`, не по тому, что агент написал в отчёте.
